## 产品概述

实现发布系统应用创建时与 GitLab CE、Jenkins、Harbor 的自动化联动，以及配置包生成上传功能。

## 核心功能

1. **项目创建联动**：创建项目时自动在 GitLab 创建同名 Group
2. **模块创建联动**：创建模块时自动在对应 GitLab Group 下创建 Subgroup
3. **应用创建联动**：创建应用时自动创建 GitLab Repository、Jenkins CI/CD Job、Harbor Project
4. **配置包生成**：根据应用配置生成配置包（JSON/YAML格式），上传到本地文件服务器
5. **配置管理**：使用 Django 系统配置表(system_config)管理 GitLab/Jenkins/Harbor 连接配置

## 命名规范

- GitLab Group: `{project_code}`
- GitLab Subgroup: `{project_code}/{module_code}`
- GitLab Repository: `{project_code}/{module_code}/{app_code}`
- Jenkins CI Job: `{project_code}/{module_code}/{app_code}-ci`
- Jenkins CD Job: `{project_code}/{module_code}/{app_code}-cd`
- Harbor Project: `{project_code}-{module_code}`

## 技术栈

- **后端框架**: Django 5.2.1 + Django REST Framework 3.16.0
- **异步任务**: Celery 5.x（已有配置）
- **HTTP客户端**: requests 2.32.3（已安装）
- **缓存**: Redis + django-redis
- **前端**: Vue 3 + TypeScript + Vben Admin + Ant Design Vue

## 实现方案

### 服务层架构

采用分层服务架构，创建独立的服务层处理外部系统交互：

```
View Layer (视图层)
    ↓
Service Layer (服务层)
    ├── ConfigService (配置获取)
    ├── GitLabService (GitLab API)
    ├── JenkinsService (Jenkins API)
    ├── HarborService (Harbor API)
    └── ConfigPackageService (配置包生成)
    ↓
External APIs (外部系统)
```

### 配置管理

使用 system_config 表存储连接配置，配置键名规范：

- `gitlab_url`: GitLab 服务地址
- `gitlab_token`: GitLab Access Token
- `gitlab_root_group`: 根组ID（可选）
- `jenkins_url`: Jenkins 服务地址
- `jenkins_user`: Jenkins 用户名
- `jenkins_token`: Jenkins API Token
- `harbor_url`: Harbor 服务地址
- `harbor_user`: Harbor 用户名
- `harbor_password`: Harbor 密码

### 异步处理策略

应用创建涉及多个外部系统调用，使用 Celery 异步任务：

1. 创建 GitLab Repository（同步，获取 git_url）
2. 创建 Jenkins CI/CD Job（异步）
3. 创建 Harbor Project（异步）
4. 记录同步日志

### 错误处理

- 实现幂等性检查：创建前先检查资源是否存在
- 失败重试机制：Celery 任务自动重试
- 详细日志记录：记录到 SyncLog 表

## 关键接口设计

### GitLabService 核心方法

```python
class GitLabService:
    def create_group(self, name: str, path: str) -> dict  # 创建 Group
    def create_subgroup(self, name: str, path: str, parent_id: int) -> dict  # 创建 Subgroup
    def create_project(self, name: str, path: str, namespace_id: int) -> dict  # 创建仓库
    def group_exists(self, path: str) -> bool  # 检查是否存在
```

### JenkinsService 核心方法

```python
class JenkinsService:
    def create_folder(self, name: str, parent: str = None) -> bool  # 创建文件夹
    def create_pipeline_job(self, name: str, folder: str, config: dict) -> bool  # 创建 Pipeline
    def job_exists(self, full_name: str) -> bool  # 检查是否存在
```

### HarborService 核心方法

```python
class HarborService:
    def create_project(self, name: str) -> dict  # 创建项目
    def project_exists(self, name: str) -> bool  # 检查是否存在
    def create_robot_account(self, project_id: int, name: str) -> dict  # 创建机器人账号
```

## 实现要点

### 性能优化

- 配置缓存：系统配置使用 Redis 缓存，减少数据库查询
- 并发创建：GitLab、Jenkins、Harbor 资源可并行创建（使用 Celery chain/group）
- 超时控制：HTTP 请求设置合理超时（连接5s，读取30s）

### 日志记录

- 复用现有 SyncLog 模型记录同步日志
- 同步类型增加：`gitlab`、`jenkins`、`harbor`
- 记录请求/响应关键信息，便于问题排查

### 爆炸半径控制

- 外部系统不可用时不阻塞主流程
- 创建失败时记录日志，支持手动重试
- 资源创建状态通过 API 返回前端展示
